# ShopKZ — интернет-магазин + тестовый проект (Node.js / Express / SQLite)

Учебный сайт-магазин и одновременно объект тестирования для практических работ по QA
(анализ требований → STLC → 4 уровня тестирования → пирамида тестирования).

---

## 1. Установка (один раз)

Нужен **Node.js 18+**. Проверить: `node -v`

```bash
cd shopkz-project
npm install
```

Это поставит и рабочие зависимости (express, better-sqlite3, bcryptjs), и тестовые
(jest, supertest, playwright).

## 3. Структура проекта

```
shopkz-project/
├── server.js              # Express-сервер, все REST API маршруты
├── db.js                  # схема SQLite + начальные (seed) данные
├── utils.js                # чистые функции без побочных эффектов (для Unit-тестов)
├── public/                # фронтенд (то, что видит пользователь в браузере)
│   ├── index.html
│   ├── styles.css
│   └── app.js
├── tests/
│   ├── unit/               # Unit-тесты — тестируют utils.js в изоляции
│   ├── integration/         # Integration-тесты — API + реальная БД (in-process, supertest)
│   ├── system/              # System-тест — сервер поднимается отдельным процессом
│   ├── acceptance/          # Acceptance-тесты — бизнес-критерии (Given/When/Then)
│   └── e2e/                 # E2E-тест — Playwright, настоящий браузер
├── test-reports/           # СОХРАНЁННЫЙ вывод реальных прогонов тестов + журнал дефектов

├── playwright.config.js
└── package.json
```

## 4. Как самостоятельно прогнать каждый уровень тестирования

### 4.1 Unit-тесты (изолированные функции, БД не используется)
```bash
npm run test:unit
```
Что тестируется: `utils.js` — `luhnOk`, `calcOrderTotal`, `calcAverageRating`,
`isValidEmail`, `clampQty`, `isFreeCancelWindow`, `genId`.

### 4.2 Integration-тесты (API + SQLite вместе, в одном процессе)
```bash
npm run test:integration
```
Что тестируется: связки компонентов — маршрут ↔ таблица БД ↔ сессия
(регистрация↔users, корзина↔products/carts, заказ↔orders/products, права доступа админа).
Используют отдельную временную БД, поэтому вашу рабочую `shopkz.db` не трогают.

### 4.3 System-тест (сервер поднимается по-настоящему, как отдельный процесс)
```bash
npm run test:system
```
Это обычный Node-скрипт (не Jest): он сам запускает `node server.js` на порту 4310
с временной базой, стучится к нему по-настоящему через HTTP (`fetch`), проверяет
сквозной сценарий (каталог → корзина → промокод → заказ → админ меняет статус),
и глушит сервер в конце. Результаты сохраняются в `tests/system/system-results.json`.

### 4.4 Acceptance-тесты (бизнес-критерии приёмки)
```bash
npm run test:acceptance
```
Проверяют не техническую связку, а бизнес-правила: "заказ с невалидной картой не
создаётся", "промокод даёт ровно заявленную скидку", "отменить можно только в течение
30 минут" и т.д. — сформулированы в стиле Given/When/Then.

### 4.5 Всё сразу (Unit + Integration + Acceptance) + покрытие кода
```bash
npm test                # без замера покрытия
npm run test:coverage   # с замером покрытия (% строк/веток/функций)
```
После `test:coverage` откройте `coverage/lcov-report/index.html` в браузере —
наглядный построчный отчёт, какие строки кода тесты не затронули.

### 4.6 E2E-тест (настоящий браузер, кликает по интерфейсу)
Единственный уровень, который нельзя было прогнать в песочнице Claude — там нет
доступа к скачиванию браузерных бинарников. У себя в VS Code это делается так:
```bash
npx playwright install     # один раз — скачивает Chromium/Firefox/WebKit
npm run test:e2e
```
Playwright сам поднимет сервер на порту 3100 (см. `playwright.config.js`), откроет
браузер, зарегистрирует пользователя, найдёт товар, положит в корзину, оформит заказ
и проверит результат — ровно так, как это делал бы живой человек.
Если что-то упадёт — Playwright сохранит скриншот и трассировку в папке `test-results/`.

## 5. Как дописать тест самостоятельно (шаблон)

Unit-тест (файл в `tests/unit/`):
```js
const { luhnOk } = require('../../utils');

test('моё новое имя теста', () => {
  expect(luhnOk('4532015112830366')).toBe(true);
});
```

Integration-тест (файл в `tests/integration/`) — копируйте структуру
`tests/integration/api.test.js`: там уже настроены временная БД и `supertest.agent(app)`
для сессий с cookie.

После любого нового теста — просто `npm test`.

## 7. Работа в VS Code — что где менять

| Хотите изменить... | Открывайте файл |
|---|---|
| Внешний вид / цвета / шрифты сайта | `public/styles.css` |
| HTML-каркас страницы (шапка, `<head>`) | `public/index.html` |
| Логику интерфейса, что происходит по клику, все "страницы" (каталог, корзина, checkout…) | `public/app.js` |
| Любой API-маршрут (`/api/...`), правила проверки, бизнес-логику сервера | `server.js` |
| Структуру таблиц БД и начальные (seed) товары/пользователей/промокоды | `db.js` |
| Чистые функции без побочных эффектов (расчёт скидки, Luhn-проверка карты и т.п.) | `utils.js` |
| Порт, путь к БД, секрет сессии | `.env` (скопируйте из `.env.example`) |

Рекомендуемые расширения VS Code уже прописаны в `.vscode/extensions.json` —
при открытии проекта VS Code сам предложит их установить (Jest-раннер с зелёными/красными
галочками прямо в редакторе, SQLite-просмотрщик для `shopkz.db`, Playwright-раннер, ESLint).

Для отладки с точками останова: вкладка **Run and Debug** (Ctrl+Shift+D) → выберите
конфигурацию из `.vscode/launch.json` (например, «ShopKZ: запустить сервер (отладка)») → F5.
Можно ставить breakpoint прямо в `server.js` или `app.js` и смотреть значения переменных.

### Работа с git / выгрузка на GitHub

Исходный архив не содержал каталога .git. Проект перенесён в репозиторий
https://github.com/DiasIsenov06/ShopKZ. Для уже созданной локальной копии git можно использовать:

```bash
git remote add origin https://github.com/DiasIsenov06/ShopKZ.git
git branch -M main
git push -u origin main
```

Дальше обычный цикл: `git add -A && git commit -m "описание изменений" && git push`.
`node_modules/`, `.env` и файлы БД (`*.db`) уже в `.gitignore` — в репозиторий не попадут.
