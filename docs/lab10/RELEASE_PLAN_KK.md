# ShopKZ: релиз жоспары және кері қайтару

Бұл жоспар `docs/project-plan.md` ішіндегі R1–R3 күндерімен сәйкестендірілген. Уақыт белдеуі: Asia/Qyzylorda, UTC+05:00. Күндер — жоспар; релиз өтті деген дәлел емес. Жоба оқу дүкені: демо аккаунттар, in-memory сессиялар және төлем имитациясы бар. Көпшілікке арналған коммерциялық production ретінде қабылданбайды. Осы жұмыста production — команданың бекітілген оқу қабылдау ортасының атауы; егер ондай орта болмаса, production оқиғасы тіркелмейді.

## Орналастыру тәртібі

Бұл архив дайын серверді немесе іске қосылған production-ды қамтымайды. Қабылдау серверінде Node.js 24, Python 3 және жүйелік сервис алдын ала орнатылады. Ұсынылатын құрылым: `/srv/shopkz/releases/<SHA>`, `/srv/shopkz/current`, `/srv/shopkz/shared/shopkz.db`, `/srv/shopkz/backups/`. Сервис current/server.js арқылы іске қосылады; `SHOPKZ_DB_PATH` shared базасына көрсетеді. Орта параметрлері release архивінен тыс сақталады. HTTPS және сыртқы қолжетімділік сервердің жеке конфигурациясына жатады.

Артефакт GitHub Actions → нақты сәтті run → `shopkz-<SHA>` ішінен алынады. tar.gz таза release каталогына ашылады; `sha256sum -c SHA256SUMS` орындалады; `npm ci --omit=dev` орындалады. Дайын артефакт жаңа SHA үшін қайта құрастырылмайды. Сервис тоқтаған соң current сілтемесі жаңа каталогқа ауыстырылады да сервис іске қосылады. Smoke тексеру жаңа бос DB-мен staging-та орындалады; жұмыс базасындағы тест тапсырыстарын QA бөлек белгілейді.

Қабылданған нақты орналастырудан кейін ғана:

```bash
python scripts/record-deployment.py --repo DiasIsenov06/ShopKZ --sha FULL_40_CHARACTER_SHA --state success
```

Скрипт орналастырмайды: аяқталған әрекеттің GitHub Deployments жазбасын ғана жасайды. CI-дің сәтті аяқталуы deployment емес. GH_TOKEN құқықтары: Deployments write; токен файлға немесе commit-ке жазылмайды. Егер қате орналастыру live ортада ақау туғызса, оның бұрынғы success жазбасы сақталады және `incident` issue ішінде deployment ID көрсетіледі. Live ортаға жетпеген сәтсіз орнату CFR numerator-ына кірмейді.

## Кері қайтаруды бастау шарттары

Smoke тестте login/checkout істемесе, деректер бұзылса, сервис 2 минуттан аса жауап бермесе немесе 5 минуттағы 5xx үлесі 5%-дан асса, Диас rollback шешімін қабылдайды. Бұл — жоспарлық шектер, өлшенген ағымдағы SLA емес. Мақсат: шешімнен кейін 15 минут ішінде бұрынғы тұрақты қызметті қалпына келтіру.

## Rollback чек-парағы

- [ ] Ақау басталған уақыт, зардап шеккен SHA және deployment ID жазылды; `incident` issue ашылды.
- [ ] Жаңа тапсырыстар қабылдау уақытша тоқтатылды, сервис тоқтатылды.
- [ ] Ақаулы нұсқаның DB/WAL/SHM және логтары бөлек сақталды.
- [ ] Схема өзгермесе, тек current сілтемесі бұрынғы тұрақты release-ке ауыстырылды. Жұмыс DB-і сақталды: жаңа тапсырыстар жоғалмайды.
- [ ] Схема үйлеспесе, DB-ді резервтен қалпына келтіруге Диас шешім берді; резервтен кейінгі тапсырыстарды салыстыру/қайта енгізу тізімі дайындалды. Резервті соқыр көшіруге болмайды.
- [ ] DB қалпына келтірілгенде тоқтаған сервистің ескі WAL/SHM файлдары мұрағатталды да белсенді каталогтан алынды; файл иесі мен құқықтары тексерілді.
- [ ] Қалпына келтірілген база `PRAGMA integrity_check` арқылы тексерілді.
- [ ] Қызмет іске қосылды; каталог, login, себет, тапсырыс және stock smoke тесттері өтті.
- [ ] QA қызмет қалпына келген нақты уақытты `restored_at` өрісіне UTC форматында жазды.
- [ ] Нақты rollback орналастыруы тұрақты ескі SHA үшін жаңа success deployment ретінде тіркелді.
- [ ] Пайдаланушы деректері салыстырылды; себеп пен түзету PR-ы issue-ге байланыстырылды; DORA қайта есептелді.

Сессия жадыда сақталатындықтан, процесс қайта іске қосылғанда пайдаланушы қайта кіруі мүмкін. DB қалпына келтіру соңғы резервтен кейінгі жазбаларды жоғалтуы мүмкін; сондықтан бірінші таңдау — схемасы үйлесімді кодты қайтару. Резервті SQLite backup API арқылы жасау үшін `scripts/sqlite-backup.py` берілген; оны сервис тоқтағанда қолдану және нәтижесін тексеру керек.
