# Практическая работа №5 в VS Code

Тема: проектирование Test Case и Test Scenario. Объект: оформление заказа ShopKZ.
В работе 5 сценариев, 10 Positive, 10 Negative и 8 Boundary кейсов.

## 1. Открыть проект

1. Распакуйте архив в отдельную папку, например `C:\Projects\ShopKZ_Practical5`.
2. В VS Code выберите **File → Open Folder** и откройте внутреннюю папку `shopkz-project`.
3. Слева должны быть видны `package.json`, `server.js`, `practical5` и `tests`.
4. Откройте **Terminal → New Terminal**. В этой папке выполните:

```powershell
node -v
npm -v
npm install
```

Работа проверена с Node.js 22.16.0. Если установка SQLite-зависимости не проходит на другой версии Node, используйте Node.js 22 и повторите `npm install`. PostgreSQL для этого проекта устанавливать не нужно: здесь SQLite, файл базы создаётся автоматически.
Если PowerShell пишет, что выполнение `npm.ps1` запрещено, выберите профиль терминала **Command Prompt** или используйте `npm.cmd` вместо `npm`.

## 2. Запустить сайт

```powershell
npm start
```

Откройте `http://localhost:3000`. Войдите: **test@shopkz.kz**, пароль **test1234**.
Терминал с сервером оставьте открытым. Для тестов создайте второй терминал кнопкой **+**.

## 3. Показать документацию

Откройте `practical5/test-cases.html` в браузере: в нём сценарии, требования и все кейсы с данными, шагами, ожидаемыми и фактическими результатами.
В VS Code откройте `practical5/cases.json`. Объясните один кейс, например P02:

«Пользователь уже вошёл и добавил товар. Отправляем правильную карту. Ожидаем успешный заказ, правильную сумму, очистку корзины и уменьшение остатка».

`cases.json` содержит описание проверок; `tests/practical5/checkout.test.js` их выполняет; `practical5/run.js` запускает Jest и сохраняет результаты. Не нужно вручную вводить все 28 тестов.

## 4. Показать найденный дефект

Во втором терминале выполните:

```powershell
npm run practical5:before
```

Команда запускает сохранённую исходную версию сервера из `practical5/server.before.cjs` с временной базой.
Для воспроизведения ошибки не нужно менять рабочий `server.js`.
В исходной версии ожидается **24 passed, 4 failed**. Ненулевой код завершения здесь означает, что ошибки воспроизведены.
Откройте `practical5/results/before-results.json`: N09, N10, B05, B08 возвращали HTTP 200 и создавали заказ вместо отказа.

Скажите:
«Для неправильного способа оплаты и неверного срока карты я ожидал отказ. Исходная версия создавала заказ. Поэтому тесты Failed. Это два дефекта, которые проявились в четырёх кейсах».

## 5. Показать исправление и Retest

Откройте `server.js`, найдите комментарии **D5-01** и **D5-02**.
Первое исправление допускает только `card` и `ewallet`. Второе проверяет месяц 1–12 и срок действия карты.

```powershell
npm run practical5
```

После исправления ожидается **28 passed, 0 failed**. Откройте `practical5/results/after-results.json` и сравните те же четыре ID.
В них должен быть HTTP 400; число заказов, корзина и остатки до и после запроса должны совпадать.
Объясните: «Повторное выполнение ранее упавших кейсов после исправления называется Retest».

HTML и Word фиксируют проверенный прогон, приложенный к работе. Новые запуски обновляют JSON и консольные результаты; Word и HTML автоматически не переписываются. Если результат отличается, ориентируйтесь на свежий JSON.

## 6. Показать Regression

```powershell
npm test
```

Команда выполняет существующие тесты проекта и новые кейсы. Она проверяет, что исправление не сломало другие уже проверявшиеся функции.
`npm run practical5` сам запускает приложение через Supertest, поэтому для автоматических проверок запуск `npm start` не обязателен.
API-тесты не кликают по кнопкам браузера. Проверку интерфейса покажите отдельно по шагам ниже.

## 7. Вручную показать отрицательный тест N08

1. На сайте войдите в тестовый аккаунт.
2. Добавьте один товар с положительным остатком в корзину.
3. Нажмите **Оформить заказ**.
4. Укажите адрес `г. Астана, ул. Абая 10` и телефон `+7 700 123 45 67`.
5. Выберите банковскую карту и введите **4000 0000 0000 0002**, срок **12/99**, CVV **123**.
6. Нажмите **Оплатить и подтвердить заказ**.
7. Покажите сообщение об отказе платежа. Товар должен остаться в корзине; новый заказ не должен появиться в «Мои заказы».

Скажите: «Это отрицательный тест. Он Passed, когда система правильно отклоняет ошибочные данные. Negative не означает Failed».

## 8. Вручную показать положительный тест P02

1. Вернитесь к оформлению с тем же товаром в корзине.
2. Замените номер на **4532 0151 1283 0366**, срок **12/99**, CVV **123**.
3. Подтвердите заказ.
4. Покажите созданный заказ в разделе заказов и пустую корзину.

Это учебная имитация оплаты; сайт не подключён к банковскому шлюзу. Используйте только указанные тестовые номера.

## 9. Показать граничный тест

При оформлении введите срок **13/99**: должен появиться отказ. Замените его на **12/99**: месяц разрешён.
В автоматическом наборе дополнительно есть длина карты 15/16/17 цифр, CVV 2/3/4 цифры и месяц 00/01/12/13.
Часть значений длиннее ограничения поля, например CVV из 4 цифр, проверяется через API: HTML `maxlength` мешает обычному вводу, но сервер тоже должен защищать данные.

## 10. Что показать и какие скриншоты сделать

1. Таблицу сценариев и кейсов в Word или HTML.
2. Терминал с первым запуском: 24 passed / 4 failed.
3. `server.js` с исправлениями D5-01 и D5-02.
4. Терминал с повторным запуском: 28 passed / 0 failed.
5. Сайт с отказом тестовой оплаты и созданным корректным заказом.
6. Матрицу требований R01–R09 и связанных тестов в отчёте.

Перед демонстрацией достаточно пройти шаги 1–2. Во время защиты покажите шаги 3–5 и один ручной кейс. Скриншоты интерфейса снимайте после выполнения этих действий на своём компьютере.
